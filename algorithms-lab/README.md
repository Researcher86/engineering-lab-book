# Книга Algorithms Lab

> Статус: **7 глав готовы**. Код закреплён тегом
> [`v1.0.0`](https://github.com/Researcher86/algorithms-lab/releases/tag/v1.0.0).

Учебник по алгоритмам и структурам данных, написанный по коду лаборатории
[`algorithms-lab`](https://github.com/Researcher86/algorithms-lab). Каждая
глава разбирает один механизм на настоящем PHP-коде, показывает эксперимент
и числа, а затем явно перечисляет, что осталось за пределами измерения.

Это не сборник решений Codeforces и не пересказ README. Лаборатория отвечает
на вопрос «что здесь реализовано», а книга — на вопрос «почему это работает,
сколько стоит и где ломается».

## Что вы сможете

Книга рассчитана на PHP-разработчика, который уже писал код и хочет
разобраться в структурах данных на уровне, достаточном для чтения и
изменения библиотеки. После неё вы сможете:

- объяснить, как load factor влияет на пробы, и почему Bloom filter не
  является точным множеством;
- выбрать LRU или LFU под характер нагрузки и проверить выбор на скане,
  смене популярности и цикле `capacity + 1`;
- оценить память графа до его загрузки и понять, почему CSR компактнее
  списка;
- читать B-дерево и B+ дерево, отличать высоту от числа сравнений и не
  путать модель страниц с page cache;
- сравнить modulo, consistent hashing и rendezvous по доле перемещаемых
  ключей и стоимости lookup;
- отличить точный top-K от ограниченных summary и не обещать `O(K)` памяти
  там, где нужен `O(distinct)`;
- построить external merge sort с chunk, spill и k-way merge, посчитать
  проходы и объяснить, почему chunk в байтах не равен PHP peak;
- проверить алгоритм счётчиками и дифференциальными тестами, а не только
  секундомером.

## Как читать

Главы идут в фиксированном порядке: каждая использует идеи предыдущих.
Полный маршрут — читать 1–7 подряд. Если механизм уже знаком, главу можно
пропустить, но ссылки «→ глава N» показывают, где он разбирается.

Стандартная глава устроена так:

1. **Проблема** — зачем структура нужна и что ломается без неё.
2. **Устройство** — как она работает, с выдержками из кода.
3. **Эксперимент** — что запустить, чтобы увидеть механизм живым.
4. **Что ломается** — ограничения, failure modes и честные оговорки.
5. **Как это проверено** — тесты, счётчики и инварианты.
6. **Что запомнить** — сжатый итог.
7. **Упражнения** — задачи на понимание и измерение.

Выдержки кода скопированы из файлов как есть и снабжены ссылкой на GitHub с
диапазоном строк. Ссылки привязаны к тегу `v1.0.0`, а не к ветке `master`,
поэтому номера строк не «уплывут» после следующих коммитов. Комментарии в
коде лаборатории на английском; книга на русском.

## Как запустить

Все команды выполняются в Docker-контейнере проекта; на хост не нужно
ставить PHP или расширения. Если репозиторий лаборатории лежит рядом с
книгой:

```bash
cd ../../algorithms-lab
make build install      # один раз
make check              # PHPUnit + PHPStan + PHP-CS-Fixer
make experiment         # список экспериментов
make scenario           # интеграционный сценарий
```

Полный список экспериментов и бенчмарков — в `make experiment` и
`make benchmark`; измеренные таблицы с окружением лежат в
[`docs/BENCHMARKS.md`](https://github.com/Researcher86/algorithms-lab/blob/v1.0.0/docs/BENCHMARKS.md).
Числа в главах — один прогон в Docker на виртуализированном Linux, а не
универсальная константа. Сравнивайте форму кривых и счётчики, а не только
миллисекунды.

## Проверка книги

Каждый показанный код-блок сверяется с закреплённым тегом и диапазоном
строк; все GitHub-ссылки проверяются на существование файла и валидность
диапазона; локальные ссылки README должны резолвиться. Из каталога книги:

```bash
python3 ../php-systems-lab/tools/check_book.py \
  --expected-chapters=7 \
  --source-root ../..
```

`--source-root ../..` читает локальные репозитории без сети и ожидает
структуру `<repo>/<path>`, то есть `engineering-lab/algorithms-lab/...`.
В CI тот же checker запускается с `--expected-chapters=7` для Algorithms Lab
и с обычными 26 главами для PHP Systems Lab.

## Что не обещается

- Это не рейтинг алгоритмов. Числа зависят от PHP, Docker, хоста и формы
  данных; в главах указано, где именно сделан один прогон.
- Это не полный B+ write path: B+ deletion не реализован.
- Это не production-кэш: LFU без decay, LRU без сегментации, без
  распределённого кэша.
- Это не replication protocol: `getNodes(R)` возвращает порядок fallback, а
  не копирует данные.
- Это не формальная гарантия top-K: bounded summaries дают кандидатов с
  ошибкой, зависящей от распределения.
- Это не замена page cache: модель страниц считает обращения к узлам, а не
  физические чтения.
